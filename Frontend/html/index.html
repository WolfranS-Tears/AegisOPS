Arquitectura RAG

  1. 01El frontend envía la descripción del incidente a la API de Spring Boot.
  2. 02Spring Boot registra la consulta y llama al flujo RAG de n8n.
  3. 03n8n genera el embedding con OpenRouter y busca en Qdrant los artículos más similares sobre el umbral.
  4. 04Solo los artículos activos y verificados en PostgreSQL llegan al modelo, que responde con pasos y fuentes.
  5. 05Spring Boot valida las fuentes, guarda la respuesta y permite calificarla de 1 a 5.

Reglas de seguridad

  • verified_userEl navegador nunca consume n8n, Qdrant ni OpenRouter: todo pasa por Spring Boot.
  • keyClaves de API y credenciales solo en variables de entorno y credenciales de n8n.
  • blockSin fuentes relevantes, el asistente lo informa en lugar de inventar una solución.
  • databaseEl dashboard muestra cálculos SQL verificables, nunca cifras generadas por la IA.
